# Implementation Work Brief

Use this after an authorized idea or maintainer request has a selected outcome. Keep the record in
its existing planning or delivery home and link it from private runner state. A completed template
records scope; it does not grant authority.

- Foundational, breaking or security-sensitive decisions requiring maintainer review:

Carry forward the existing trusted request. A bot recommendation, priority or connector-authored
Approved label cannot replace a human decision. Routine implementation choices within the accepted
outcome remain autonomous; a material scope change needs a revised decision.

## UI Intent

For UI work, name the target screen, primary Navet reference family, primitives and composition
recipe. State the reading order, primary action, density, responsive behavior and shared tokens.
Identify realistic data and loading, empty, error, unavailable and permission states. Explain any
missing reusable behavior or proposed exception before creating a feature-local foundation.

For nonvisual work, mark this section not applicable and explain why.

## Delivery And Verification

List small implementation slices, direct consumers, dependencies and persistence/provider risks.
Specify observable acceptance criteria and the narrow checks that prove each one. For UI, include
relevant viewports, all four themes, touch, keyboard, reduced motion and state transitions. Separate
real-runtime evidence from stories and fixtures. Record documentation impact and affected guides.

## Execution And Recovery

Link the owning task, worktree, branch and PR. Record resource policy, retry limits, next action and
questions requiring input. Missing usage measurements are unknown, not zero. Preserve the request
identity and unfinished state across interruption. Prepare the [approval package](approval-package.md)
from current-head evidence when implementation and review are complete.

Record the accepted request time and its owning-service reference before execution. Preserve native
dispatch, progress, waiting, interruption and resume receipts under that request identity. Define
the stall threshold and what counts as a duplicate dispatch before measuring them. Capture the
first submitted result separately from repairs and the accepted result. Record maintainer
interventions and review time only from independently observed human activity; commit counts,
review comments and agent estimates cannot establish those measurements.
